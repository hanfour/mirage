### harness 改了什麼

前一位實作者留下未 commit 的改動，本次收尾時保留三項、換掉一項：

**保留**：
- `LOAD_LIMIT` 8 → 18（原本訂在常態負載下緣，幾乎每輪都被擋）
- `load_gate` 被擋時重試該輪而非跳過（原本 `-r 3` 只吃得到 1 輪）
- 每輪清掉 `NSWindow` 的 frame-autosave（避免「這輪能不能收斂」看上一輪臉色）

**換掉（全螢幕 → 仍是全螢幕，但改變自動化手段）**：原本（未 commit 的版本）打算送
⌃⌘F 鍵並輪詢重試；本次收尾時**手動實測**（見下方「全螢幕自動化的發現」）發現鍵送在
這台機器上確實不可靠，但也發現一個更可靠的替代——直接對視窗寫 Accessibility 屬性
`AXFullScreen = true`，不經過鍵盤事件佇列、不依賴 frontmost。腳本內的長註解記載了完整
推導；本節摘要結論。

### 全螢幕自動化的發現

1. **鍵送（⌃⌘F）確實不可靠**：依賴 MirageApp 是 frontmost／key window，這台共用機器
   上任何搶焦點的東西都會讓鍵送空。
2. **`osascript -e 'tell application "System Events" to set value of attribute "AXFullScreen" of window 1 to true'` 更可靠**：不需要 frontmost，連續多次全新啟動測試中觸發率遠高於鍵送。
3. **視窗放大（改設視窗尺寸）這條路線經實測證明在本機不可行，不是不可靠而是結構上到不了**：
   本機螢幕（邏輯 1680×1050）下，視窗高度會被 macOS 限制在螢幕可視高度以內
   （`constrainFrameRect`），無論用 `System Events` 的 `set size` 怎麼設，最終都會被拉回
   視窗模式的天花板 —— 實測穩定收斂在 **888×1972**，到不了 900。
4. **真全螢幕（AXFullScreen）在本機也到不了字面上的 900×2000**：用 `CGWindowListCopy-
   WindowInfo` 核對過 MirageApp 視窗全螢幕後確實佔滿整片螢幕（`{0,0,1680,1050}`，與
   `NSScreen.main.frame` 一致），但串流尺寸連續三次全新啟動都只收斂到同一個數字
   **898×1996**（不是隨機抖動，是穩定終態）。回推幾何：`content_height_pt ≈ 998`，比
   螢幕邏輯高度 1050 短少恰好 52pt——與 `MirageScene.swift` 的 `ZStack` 沒有呼叫
   `.ignoresSafeArea()` 吻合（SwiftUI 在全螢幕下為選單列收回熱區保留的安全區）。這是
   產品碼行為，修它超出本次「不動產品碼」的範圍。
5. **898×1996 ≈ 1.79 MP，離 `StreamSize.maxPixels`（1.8 MP）僅約 0.4%**——量測上視為
   已達解析度上限。腳本的收斂判定因此從「字面等於 900x2000」改成「寬度 ≥ 896」（數值
   門檻，見 script 內 `FULLSCREEN_MIN_WIDTH`）。這條門檻仍能正確分辨「有沒有真的進
   全螢幕」（視窗模式天花板 888 vs 全螢幕天花板 898），只是不強求湊到本機到不了的
   整數 900。**注意這與前一版計畫文件（`docs/plans/.../remeasure.md` 的「2026-08-04
   更正」一節）設想的「改用放大視窗」不同**——那個方案經實測證明比全螢幕更差（888 <
   898），本次改用「更可靠的全螢幕觸發手段」而非「放棄全螢幕」。
6. **對驗收線 7 字面條件的偏離、及其方向**：量到的是 898×1996，不是文字面上的
   900×2000，差距僅約 0.2%（寬度）／0.4%（像素）。方向難以嚴格歸類為「保守」或
   「樂觀」——與真正的 900×2000 相比，1.79MP vs 1.8MP 只差一點點畫面資訊量，實務上
   對 fps 的影響應在量測雜訊範圍內，遠小於 round-to-round 的自然波動（見下方數字，
   同一次呼叫內三輪就有 38–60 fps 的散布）。

### ⚠️ `FULLSCREEN_MIN_WIDTH=896` 綁定本機螢幕幾何，換機器要重新核對

888（視窗模式天花板）／896（門檻）／898（全螢幕天花板）這三個數字全部是在「這片邏輯
1680×1050 螢幕」上量出來的，896 目前卡在中間、留了看似安全的邊界，但 898−888=10 這個
邊界其實很窄。**這條門檻沒有論證過反向風險**：換一台視窗模式天花板剛好落在 890–896
