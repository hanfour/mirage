# 鏡像視窗操作對齊 iPhone 鏡像輸出

- 日期：2026-10-01
- 分支：`feat/mirroring-parity`

## 目標

使用者用 macOS 的 iPhone 鏡像輸出操作手機，希望 Mirage 的鏡像視窗用起來一樣。這次做五項：

| # | 項目 | 現況 |
| --- | --- | --- |
| 1 | 標題列右側放「主畫面」「最近任務」兩個圖示按鈕 | 只在選單列的下拉選單裡 |
| 2 | 觸控板雙指滑動轉成 Android 的手指拖曳 | 完全沒有處理捲動事件，雙指滑動沒有反應 |
| 3 | 預設視窗大小與 iPhone 鏡像輸出相同，仍可縮放 | 預設內容 459×992 |
| 4 | ⌘1 主畫面、⌘2 最近任務 | 沒有快捷鍵 |
| 5 | 標題列平時隱藏，滑鼠移到視窗上緣才出現 | 一般標題列 |

不做：返回鍵按鈕（使用者決定；返回維持 Esc 與選單列）、手機外型圓角視窗、一般滑鼠滾輪（非觸控板、沒有 phase 的捲動事件）。

## 1. 標題列按鈕

- 兩個圖示按鈕放在標題列右側，順序與 iPhone 鏡像輸出相同：左邊主畫面、右邊最近任務。
- 圖示用 SF Symbols，選最接近 iPhone 鏡像輸出的外觀：主畫面用點陣格狀圖示（例如 `square.grid.3x3.fill`），最近任務用並排視窗圖示（例如 `rectangle.on.rectangle`）。
- 滑鼠停留顯示說明：「主畫面（⌘1）」「最近任務（⌘2）」。
- 動作與選單列的「主畫面」「最近任務」相同，送 W3C key `GoHome`、`AppSwitch`。
- 沒有連線時按鈕停用。

## 2. 雙指滑動轉手指拖曳

只處理 `hasPreciseScrollingDeltas == true` 且帶 phase 的捲動事件（觸控板、巧控滑鼠）。

| 事件 | 動作 |
| --- | --- |
| `phase == .began` | 在游標位置按下一根手指 |
| `phase == .changed` | 手指位置加上 `scrollingDeltaX/Y`（視窗點數，換算成正規化座標），超出畫面時夾在邊緣 |
| `phase == .ended` 或 `.cancelled` | 在最後位置放開 |
| `momentumPhase != []` | 忽略。手指放開後的慣性由 Android 依放開前的速度自己計算 |

- 移動方向跟隨 `scrollingDelta`，也就是畫面內容跟著手指走（macOS 預設的自然捲動）。使用者關掉自然捲動時方向跟著反轉，與他在 macOS 的設定一致。
- 走既有的單指觸控路徑（`MirrorView` 的 `onMouse`），不新增觸控槽位。
- 以下情況不處理捲動：滑鼠左鍵正按著（避免兩條路徑搶同一根手指）、滑鼠鎖定中（遊戲鍵位模式的視角控制）、鍵位編輯模式。
- 拖曳途中視窗失去焦點、被隱藏或斷線時，要放開手指，不能在 guest 留一根按著的手指。
- 捲動事件改用視窗層級的 local event monitor 接收，再依游標位置換算座標。原因：標題列出現時，游標在上緣的捲動事件會落在標題列，送不到鏡像畫面；Android 的通知欄要從最上緣往下拉，必須讓上緣的雙指下滑也能送進 guest。
- 「phase 序列 → 按下／移動／放開」的判斷寫成純型別，可單元測試。

## 3. 預設視窗大小

- iPhone 鏡像輸出的視窗是 326×720 pt。Mirage 改成標題列隱藏後內容區等於整個視窗，預設內容大小改為 324×720（guest 9:20，寬度取偶數）。
- `minimumContentSize` 維持 270×600。
- 沒有存過位置時才用預設值。開發機與既有使用者都存過 `mirage-mirror` 的位置，會一直看不到新預設，所以 autosave 名稱改為 `mirage-mirror-v2`，第一次啟動新版時會回到預設大小與置中，之後照常記憶。
- 視窗變小後，Mirage 依視窗寬度向模擬器要的畫面解析度也會變小（324 pt × 2 = 648 px 寬）。全螢幕時照舊放大到上限。

## 4. 快捷鍵

- ⌘1 送 `GoHome`，⌘2 送 `AppSwitch`，比照 `MirrorRootView` 裡 ⌘S、⌘↑ 的隱藏按鈕寫法。
- 選單列的「主畫面」「最近任務」項目旁顯示對應快捷鍵。

## 5. 標題列平時隱藏

- 視窗維持 `.titled`（全螢幕與驗證腳本的 AX 全螢幕都依賴它），加 `.fullSizeContentView`、`titlebarAppearsTransparent = true`、`titleVisibility = .hidden`，讓畫面延伸到整個視窗。
- 標題列（三個視窗按鈕與第 1 項的兩個按鈕）平時透明度 0，滑鼠進入視窗上緣 32 pt 時淡入，離開後淡出，動畫 0.15 秒。
- 標題列隱藏時，上緣的點擊要送進 Android；標題列顯示時，上緣屬於視窗（拖曳視窗、按按鈕）。這與 iPhone 鏡像輸出的行為相同。
- 全螢幕時交給系統的標題列行為，不另外處理。
- 鏡像畫面原本依內容區擺放，延伸到整個視窗後要確認：長寬比計算、左下角的文字輸入控制項、連線橫幅位置都仍正確。

## 驗收

| 項目 | 方式 | 負責 |
| --- | --- | --- |
| 雙指拖曳的 phase 判斷 | 單元測試：began／changed／ended、momentum 忽略、邊緣夾住、左鍵按著時不處理、中途失焦會放開 | codex |
| 雙指拖曳實機 | 用 CGEvent 合成帶 phase 的捲動事件；guest 的 `getevent` 看到一次 `ABS_MT_TRACKING_ID` 按下與放開、位置有移動；最近任務畫面左右切換有反應 | PM |
| 預設大小 | 刪掉 v2 的 autosave 後啟動，量到視窗 326×720 左右 | PM |
| 全螢幕不受影響 | `verify_fps_fullscreen.sh` 照常收斂到上限並通過 | PM |
| 按鈕與快捷鍵 | ⌘1、⌘2 與兩個按鈕各觸發一次，guest 畫面切換 | PM |
| 標題列淡入淡出、上緣點擊、整體手感 | 人工試用 | 使用者 |
